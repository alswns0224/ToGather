# 회의 안건 자료·산출물과 Slack 연결 Task 표시

2026-11-20. 설계 대조의 우선순위 6번을 보완했다. G03(회의 안건별 관련 자료·산출물, SD-10-05 본문 74쪽)과 G05(Slack 대화의 연결 Task, SD-11-02 본문 77쪽)에 해당한다.

원본 저장소 `feature/c-fix-task-rules`의 앞선 변경 위에 화면 연결을 추가했다. 서버 API·DB·공유 인터페이스는 변경하지 않았으며 별도 UI 실험본은 수정하지 않았다.

## 회의 안건

- 각 안건에 ‘자료·산출물 보기’를 제공한다. 펼칠 때 해당 Task의 기존 협업 맥락 API를 호출하고, 접었다 다시 펼치거나 새로고침하면 최신 내용을 조회한다.
- 관련 자료와 Task 생성 근거 자료를 ID 기준으로 중복 없이 표시한다. 출처, 제목, 보관 내용, 원본 링크를 제공한다.
- 기존 ContextContentCard를 재사용해 원본 삭제 시 보관 사본 안내와 Drive 휴지통·연동 폴더 밖 이동 구분을 유지한다. 삭제된 원본과 HTTP/HTTPS가 아닌 주소는 원본 링크로 표시하지 않는다.
- 산출물 이름·확장자·제출 파일명·제출 여부·원본 파일 링크와 제출 개수/전체 개수를 표시한다. 실제 제출·항목 편집은 ‘Task에서 제출·관리’로 이동한다.
- 자료 조회로 받은 최신 제목·진행률·상태·위험도를 안건 머리에도 반영한다. 삭제된 Task는 조회 버튼을 표시하지 않는다.
- 불러오는 중, 자료·산출물 없음, 조회 실패와 재시도를 구분한다. 화면을 바꾸거나 안건을 접은 뒤 늦게 도착한 응답은 무시한다.
- 좁은 영역에서는 제목과 진행률을 줄바꿈해 제목이 눌리거나 버튼이 잘리지 않게 한다.

## Slack

- 채널 메시지, 스레드 첫 메시지, 답글에 ‘연결된 Task’를 표시한다. 제목, 진행 중/완료, 진행률과 Task 상세 링크를 제공한다.
- 채널 메시지와 답글은 펼칠 때만 조회한다. 선택한 스레드의 첫 메시지는 연결 목록을 바로 표시한다. 메시지 전체에 대한 조회 요청을 한꺼번에 보내지 않는다.
- 기준은 기존 역조회 API의 **해당 메시지 연결**이다. 스레드 전체 답글의 Task를 첫 메시지에 합산하지 않는다.
- 연결 없음, 불러오는 중, 실패와 재시도, 새로고침을 제공한다. 저장 ID가 없는 미동기화 메시지는 조회 대신 동기화 후 확인 안내를 표시한다.
- 연결 목록과 Task 링크 클릭이 메시지의 스레드 열기 동작으로 전파되지 않게 한다.
- 워크스페이스·채널·스레드별로 화면을 구분해 다른 대화의 조회 상태를 재사용하지 않는다. 기존 Slack 메시지 작성·수정·삭제와 논의 분석 동작은 유지한다.

## 재사용한 조회 API

- `GET /api/workspaces/{workspaceId}/tasks/{taskId}/context`
- `GET /api/workspaces/{workspaceId}/contents/{contentRefId}/tasks`

로그인·워크스페이스·Task/콘텐츠 소속과 팀 콘텐츠 필터링은 기존 서버 경로를 사용한다. 이번 변경에서 서버 조회 범위나 역방향 연결 기준을 확장하지 않았다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| `frontend/npm run build` | 타입 검사·배포 빌드 성공 |
| `backend/gradlew.bat build` | 성공. 백엔드 변경이 없어 기존 빌드·테스트 결과를 재사용(UP-TO-DATE) |
| 브라우저 동작 확인 | 서로 다른 19개 시나리오 통과. 회의·Slack 각각 1440px와 390px 영역에서 반복 확인 |
| 화면 배치 | 실제 서비스 스타일을 적용한 확인용 화면을 캡처해 넓은 영역·좁은 영역 배치 확인 |
| `git diff --check` | 통과 |

브라우저 확인은 실제 페이지에 들어가는 컴포넌트와 공통 API 호출 코드를 사용하고 응답만 확인용 데이터로 대체했다. 지연 조회, 최신 진행률, 자료 중복 제거, 제출·미제출, 원본 삭제·이동·휴지통, 안전한 원본 링크, 빈 목록, 실패 후 재시도, Task 이동과 클릭 전파 방지, 새로고침, 미동기화 메시지 안내, 좁은 영역의 넘침을 점검했다.

결과와 화면은 작업 폴더의 `output/context-ui-20261120`에 있다. 개발 서버·사용자 DB·실제 Slack/Google 계정을 사용한 통합 E2E는 이번 검증에 포함하지 않았다. 확인용 임시 서버와 브라우저는 종료했다. 기존 500kB 초과 번들 경고는 남아 있다.

커밋·푸시·머지는 하지 않았다. 다음 우선순위는 팀 전체·담당자별 진행률/위험도 집계와 서버 필터다.
