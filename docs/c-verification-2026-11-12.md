## C-06 자료 100건·1,000건 성능

별도 Task 두 개에 자료를 각각 100건과 1,000건 연결했다. 자료는 Slack·Notion·Drive에 나누었고 원문은 건당 약 1KB다. 일부 자료는 원본 삭제와 사본 상태다. 로컬 단일 사용자가 순차 조회한 결과다.

HTTP 측정은 요청 시작부터 응답 본문 수신까지 포함했다. 규모별로 첫 요청 1회와 반복 5회, 총 6회 측정했고 매번 자료 수·상태 수·정렬을 검사했다.

| 연결 자료 | 첫 요청 | 전체 6회 범위 | 응답 크기 | 화면 전체 자료 카드 표시 |
|---|---:|---:|---:|---:|
| 100건 | 187ms | 173~187ms | 131,518B | 2,391ms |
| 1,000건 | 220ms | 220~267ms | 1,316,631B | 2,389ms |

화면 시간은 페이지 이동 직전부터 마지막 자료 카드가 표시될 때까지 자동화 호스트의 경과 시간으로 한 번씩 측정했다. 브라우저 제어 비용도 포함하며, 브라우저 자체 성능 계측이나 동시 접속 부하 테스트는 아니다. 1,000건의 모든 카드가 생성됐고 가로 넘침과 화면 오류는 없었다.

1,000건 화면에서 접근성 이름으로 마지막 버튼을 찾는 자동화 검색이 한 번 시간 초과됐다. DOM 확인과 CSS 기반 마지막 카드 확인으로 화면 자체는 정상 표시됨을 확인했다. 이 환경에서 두 규모 모두 조회 5초 이내 목표를 충족했으며, 운영 환경 성능과 실연동 공동 흐름은 별도 검증 대상이다.

## 기본 자동 동기화 복구

자동 스케줄러를 켠 상태에서 수동 동기화 요청 없이 두 차례 실행을 관찰했다. 기본 설정은 시작 후 1분, 이후 전체 동기화 작업이 끝난 뒤 5분 간격이다. 아래는 DB의 `lastSyncedAt`이며 서울 시각이다.

| 대상 | 1차 | 2차 | 최종 실패 횟수 |
|---|---|---|---:|
| Drive 테스트 폴더 A | 09:21:21.579 | 09:26:33.693 | 0 |
| Drive 테스트 폴더 B | 09:21:22.979 | 09:26:34.704 | 0 |
| 개인 Gmail | 09:21:23.596 | 09:26:35.395 | 0 |

두 차례 모두 서버의 `scheduling-1` 실행 로그로 확인했다. Drive 두 폴더와 Gmail의 cursor가 유지됐고 연결 상태는 `CONNECTED`다. 2차 Drive 동기화는 방금 업로드한 테스트 파일 1건을 처리했고 추가 변경은 없었다. 이후 DB에서도 업로드 파일은 중복 없이 1건, Gmail은 기존 27건임을 확인했다. Gmail 2차는 새 변경이 없었다.

활성 연결과 동기화 상태에는 Slack이 없어 자동 논의 분석이 실제 Gemini 호출을 수행할 대상은 없었다. 실제 Gmail 본문을 AI 분석으로 보내지 않았다.
