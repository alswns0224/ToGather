# 작업 중 외부 서비스 연결 해제 보호

2026-11-19. 설계 대조에서 정한 우선순위 3번 수정이다. `feature/c-fix-task-rules`의 기존 Task 상태·삭제 보호 변경 위에 작업했으며 커밋·푸시·머지는 하지 않았다.

## 변경된 동작

- 실제 연결을 사용 중인 업로드·동기화 등 작업이 있으면 연결 해제를 `409 CONNECTION_IN_USE`로 거절한다. 토큰과 선택한 연동 대상은 유지된다.
- 연결 해제가 먼저 시작됐으면 같은 계정으로 새 토큰을 요청하는 작업도 거절한다. 해제 예약은 DB 트랜잭션 종료까지 유지한다.
- 정상 종료·오류·취소된 트랜잭션의 예약은 반납한다. 작업이 끝나면 사용자가 다시 해제할 수 있다.
- HTTP 요청의 연결 사용을 Filter에서 추적한다. 별도 스레드에서 수행하는 수동·자동·웹훅 동기화와 자동 논의 분석에도 작업 범위를 적용한다.
- Drive 다운로드·미리보기의 비동기 스트리밍은 요청 스레드가 반환된 뒤에도 응답 완료까지 예약을 유지한다.
- 서로 다른 계정의 연결은 독립적으로 동작한다. 동일 계정의 Google Drive·Calendar·Gmail은 권한 폐기의 영향을 공유하므로 함께 보호한다.
- Google 권한 폐기 성공 후 같은 계정의 나머지 Google 연결은 `REAUTH_REQUIRED`로 표시하고 화면에 재인증을 안내한다. 다른 계정은 변경하지 않는다.
- 외부 권한 폐기를 확인하지 못해도 ToGather의 로컬 연결 해제는 완료한다. 대신 외부 서비스 설정에서 ToGather 권한을 직접 확인·해제하라는 안내를 반환한다.
- 이미 해제된 연결의 재요청은 빈 토큰을 다시 폐기하지 않는다. 과거 외부 폐기 성공 여부는 저장하지 않으므로 직접 확인 안내를 유지한다.

## 화면

- 같은 화면에서 수동 동기화 중일 때 연결 해제 버튼을 비활성화한다. 다른 탭·사용자·자동 작업과 겹치는 경우는 서버가 검사한다.
- 연결 해제 요청 처리 중에는 중복 클릭을 막고 진행 상태를 표시한다.
- 서버가 반환한 작업 중 안내, 해제 성공, 외부 권한 수동 확인, 같은 Google 계정의 다른 연결 재인증 결과를 구분해 표시한다.
- Google 연결 해제 전에는 같은 계정의 다른 서비스도 재인증이 필요해질 수 있음을 확인창에 안내한다.

## 구현과 API

- `ConnectionOperationRegistry`: 실제 토큰이 선택된 연결의 사용 예약과 해제 예약을 상호 배제한다. 토큰 문자열을 저장하지 않는다.
- `IntegrationService`의 기존 토큰 제공 메서드 시그니처는 유지한다. 예약 획득 전 읽어 둔 Entity가 오래됐더라도 DB의 최신 상태를 다시 확인해 해제되었거나 재인증이 필요한 토큰을 반환하지 않는다.
- Google 관련 연결은 반복 쿼리 대신 한 번에 조회한다.
- `DELETE /api/workspaces/{workspaceId}/integrations/connections/{connectionId}` 성공 응답은 결과 안내를 위해 기존 204에서 **200 + ApiResponse**로 변경했다.

```json
{
  "data": {
    "manualRevocationRequired": false,
    "relatedConnectionsRequireReauth": false
  }
}
```

- 작업 중 거절은 409, 로그인·멤버십·연결 소속·관리 권한 검사는 기존처럼 유지한다. 응답에 토큰이나 외부 계정의 비밀값을 넣지 않는다.
- Google·Slack 클라이언트가 폐기 실패를 숨기지 않도록 수정했다. Slack은 HTTP 200이더라도 `ok`와 `revoked` 결과를 검사한다.
- 비어 있던 Notion 폐기 메서드를 공식 OAuth 폐기 API에 연결했다. 이 호출만 공식 문서의 API 버전을 사용하며 기존 Notion 조회·검색 버전은 바꾸지 않았다.
- 이번 작업에서 DB 스키마·Entity 필드·기존 Flyway 파일은 변경하지 않았다. 이전 Task 작업의 V10 데이터 정리 파일은 그대로 유지한다.

## 검증 범위

실제 테스트용 PostgreSQL, MockMvc와 외부 응답 테스트 서버를 사용했다. 실제 외부 계정의 권한을 폐기하거나 사용자 DB에 접속하지 않았다. 실제 브라우저 조작은 이번 검증에 포함하지 않았다.

새 회귀 테스트는 다음을 검증한다.

- 업로드를 진행 중인 상태로 유지하고 동시에 해제를 요청하면 409, 업로드 종료 후 해제 성공
- 업로드 실패 뒤 예약 해제
- HTTP 요청이 아닌 백그라운드 동기화 중 해제 차단, 동기화 성공·실패 후 예약 해제
- 해제가 진행 중이면 새 작업의 토큰 요청 차단
- 해제 전 읽은 오래된 Entity로 토큰 재사용 불가
- 다른 계정의 연결 해제 허용, 같은 Google 계정의 다른 서비스 해제 차단
- Google 폐기 이후 관련 계정만 재인증 표시, 다른 계정 유지
- 외부 폐기 실패 시 로컬 해제와 수동 확인 안내, 해제 재요청 시 중복 폐기 방지
- 로그인·권한·워크스페이스 소속 검사
- 중첩 작업·중복 토큰 조회·예외 종료, 트랜잭션 종료까지 예약 유지
- 비동기 스트리밍 응답 완료까지 예약 유지와 다음 요청으로의 상태 누출 방지
- Google·Slack·Notion 폐기 요청 형식과 성공·실패 결과

## 검증 결과

| 검증 | 결과 |
|---|---|
| 최종 백엔드 `gradlew.bat build` | 성공 |
| 백엔드 전체 | 36개 테스트 묶음, 총 230개: 229개 통과·기존 1개 제외, 실패·오류 0 |
| 이번에 추가한 회귀 테스트 | 23개 모두 통과: 연결 흐름 9, 작업 예약 5, 요청/스트리밍 2, 외부 폐기 응답 7 |
| 프론트엔드 `npm run build` | 타입 검사·배포 빌드 성공 |
| `git diff --check` | 통과 |

기존 제외 테스트는 Docker PostgreSQL이 필요한 `TogatherApplicationTests.contextLoads`다. 내장 PostgreSQL을 사용하는 나머지 통합 테스트는 실행했다. 기존 500kB 초과 프론트엔드 번들 경고는 남아 있다.

## 범위와 리뷰

- 현재 한 서버에서 실행 중인 작업을 보호한다. 여러 서버로 확장할 때는 예약 정보를 공유 저장소로 옮겨야 한다.
- 공유 작업 범위 사용법은 `docs/shared-interfaces.md`에 추가했다. 공유 인터페이스 문서·여러 파트 코드 변경이 포함되므로 저장소 규칙에 따라 팀원 검토 후 반영한다.
- 기존 설계 이후 확장된 관리자·Notion 편집·웹훅 등의 기능은 유지한다.
- 다음 우선순위는 생성 후 필수 산출물 항목 추가·삭제다.

## 참고한 공식 문서

- Google은 권한 폐기가 같은 프로젝트에 부여한 범위와 토큰에 영향을 준다고 설명한다. 이 범위에 맞춰 같은 Google 계정을 함께 보호하고 재인증 상태를 반영한다. [Google OAuth 토큰 폐기](https://developers.google.com/identity/protocols/oauth2/web-server#tokenrevoke)
- Notion은 Basic 인증과 토큰 본문을 받는 OAuth 폐기 API를 제공한다. [Notion 토큰 폐기](https://developers.notion.com/reference/revoke-token)
- Slack의 폐기 성공은 HTTP 상태 외에 `ok`, `revoked` 필드로 확인한다. [Slack auth.revoke](https://docs.slack.dev/reference/methods/auth.revoke/)
