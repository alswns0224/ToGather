# Task 상태·회의 안건 삭제 규칙 보완

기준: 2026-11-19, `main`의 `c0002a2`에서 시작한 `feature/c-fix-task-rules`.
설계 대조에서 우선순위 1·2로 정한 두 규칙을 보완했다. 커밋·푸시·머지는 수행하지 않았다.

## 변경된 동작

### 산출물과 Task 상태

- 산출물이 있는 Task는 모두 제출하면 완료, 하나라도 미제출이면 진행 중이다.
- 생성 시 미제출 산출물이 있으면 요청의 상태와 무관하게 진행 중으로 시작한다.
- 수정 요청으로 제출 상태와 반대되는 상태를 지정하면 `409 TASK_STATUS_MANAGED_BY_DELIVERABLES`를 반환한다. 함께 보낸 제목 등의 변경도 저장하지 않는다.
- 현재 제출 상태와 같은 상태를 함께 보내는 기존 클라이언트의 일반 정보 수정은 허용한다.
- 산출물이 없는 Task의 수동 완료·진행 중 변경은 유지한다.
- 수정 화면에서 산출물이 있는 Task의 상태 선택 대신 자동 계산 안내와 산출물 관리 링크를 표시한다. 해당 수정 요청에는 상태를 보내지 않는다.
- Task 상세 응답에 `statusManagedByDeliverables`를 추가했다. 기존 공유 `TaskSummary` 형식은 유지했다.

### 회의 안건으로 쓰이는 Task 삭제

- `SCHEDULING`, `CONFIRMED` 상태 회의의 안건이면 삭제를 거절한다. 별도의 종료 상태가 없으므로 확정 회의의 과거 여부를 날짜로 추정해 삭제를 허용하지 않는다.
- 삭제 전에 차단 회의 목록을 조회하고, 화면에서 회의 제목·상태·이동 링크를 보여준다.
- 사전 조회를 생략하거나 조회 이후 안건이 추가된 요청도 삭제 시점에 다시 검사한다. 거절 응답은 `409 TASK_IN_ACTIVE_MEETING`이다.
- 안건 연결을 해제하거나 연결된 회의가 모두 취소되면 삭제할 수 있다.
- 정상 삭제 시 Task의 연결·산출물 등록 정보는 제거하고 원본 Drive 자료는 유지한다.
- C 파트의 `TaskDeletionService`에서 기존 공유 `MeetingService.getMeetingsByTask`를 사용한다. A 파트 Repository를 직접 조회하지 않으며 `MeetingService → TaskService`의 기존 의존 관계에 순환 참조를 추가하지 않았다.

## API

- `GET /api/workspaces/{workspaceId}/tasks/{taskId}/deletion-blockers`: 삭제를 막는 회의 요약 목록. 로그인·워크스페이스 멤버십·Task 소속을 검사한다.
- 기존 `DELETE /tasks/{taskId}`, `PATCH /tasks/{taskId}` 경로는 유지한다.

## 기존 데이터

`V10__align_task_status_with_deliverables.sql`은 이전 버전에서 수동 상태 변경으로 어긋난 Task 상태를 제출 여부에 맞춘다. 산출물이 없는 Task는 변경하지 않는다. 기존 Flyway 파일과 Entity 필드는 수정하지 않았다.

이 마이그레이션은 테스트용 PostgreSQL에서 검증했다. 실제 사용자 DB에 적용하기 위해 개발 서버를 실행하지는 않았다. 저장소 규칙상 DB 마이그레이션이 포함된 PR은 다른 두 팀원의 리뷰 후 머지해야 한다.

프론트엔드는 타입 검사와 배포 빌드를 확인했다. 실제 브라우저 화면 조작은 이번 검증에 포함하지 않았다. 기존 500kB 초과 번들 경고는 남아 있다.
