## 선택 메뉴 공통 스타일

Drive·Task·회의·Notion·논의 정리·AI 업무 보조의 단일 선택 메뉴 16곳에 공통 CSS를 적용했다. 펼친 목록은 화면 테마의 배경·테두리·둥근 모서리·그림자·스크롤을 사용한다. 선택 항목은 테마색과 체크 표시, 선택하지 않은 호버·키보드 포커스 항목은 중립색으로 구분하며 항목 사이에 4px 간격을 둔다.

HTML select와 React onChange, 필수 입력·disabled·값·키보드·폼 제출 경로는 유지한다. `appearance: base-select` 지원 브라우저에 펼친 목록 스타일을 적용하고 미지원 브라우저는 기존 선택 메뉴로 동작한다. 다중 선택·목록 상자는 이번 공통 스타일 대상에서 제외한다.

프론트 타입 검사·빌드와 `git diff --check`를 통과했다. 사용자 제공 화면에서 초기 펼침 모양을 확인한 뒤 호버 구분·간격을 보완했다. 최종 호버 수정 후 브라우저 자동 조작 검증은 하지 않았다. Computer Use가 Windows의 현재 브라우저 URL을 확인하지 못해 조작을 중단했다.

## 최종 검증과 로컬 실행

- 백엔드 `gradlew.bat build` 성공. 43개 테스트 묶음, 총 323개 중 322개 통과·기존 제외 1개·실패/오류 0. 마지막 업로드 전 빌드에서는 Java 변경이 없어 정상 결과를 재사용했다.
- 프론트 `npm run build`는 최종 호버 수정까지 포함해 통과했다. 기존 500kB 초과 번들 경고는 남아 있다.
- 기능별 확인용 API 응답을 이용한 브라우저 검증과 범위는 위 개별 문서에 기록했다. 이 결과를 실제 외부 계정 E2E 완료로 간주하지 않는다.
- 기존 로컬 PostgreSQL을 유지해 백엔드 8080·프론트 5173을 실행했고, 로컬 DB V8→V11 이전과 인증 설정 API·프록시·Drive 새 화면 모듈의 200 응답을 확인했다. 서버 실행 자체가 실제 Drive 덮어쓰기나 Calendar 변경 검증을 뜻하지 않는다.
- 남은 검증: 실제 계정에서 새 덮어쓰기·확정 회의 Calendar 수정, Slack 분석부터 Task·자료·산출물·회의까지 연결 흐름, 동시 사용자 50명 성능 목표.
- 설계 대조의 미구현 기능 G08(Slack DM의 개인별 수집과 AI 후보 탐지 입력)은 B 담당의 후속 작업이다. 기존 AI 후보 탐지 전 Gmail 수집 호출은 현재 코드에 연결돼 있다.

## 리뷰 범위

V10/V11, ContentRef·Task·Meeting Entity와 공유 DTO·서비스 인터페이스가 포함된다. Calendar·OAuth·연동·동기화와 공통 화면 스타일도 변경했으므로 A/B 두 팀원의 리뷰가 필요하다. 여러 보완이 같은 Task·ContentRef·연동 서비스에 겹쳐 있어 이슈 하나의 통합 PR로 올리고 기능별 커밋과 위 개별 문서로 리뷰 범위를 구분한다.

로컬 ZIP·사용자 DB·로그·환경 파일·빌드 결과물은 업로드 대상이 아니다. 이 PR은 리뷰를 위한 업로드이며 main 머지는 수행하지 않는다.
